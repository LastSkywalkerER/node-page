# Gateway (ingress) — publish detected services through one node

The **Gateway** (admin → Gateway) turns one node of the cluster into the public entry point: a
Traefik instance on that node terminates HTTP/HTTPS for a set of domains and forwards each to a
service running on *any* machine node-stats knows about.

Everything is declarative and replicated:

```
admin UI ──► PUT /gateway/config  ──► cluster_config["gateway_config"]   (CmdConfigSet)
         ──► POST /gateway/routes ──► gateway_routes                     (CmdGatewayRouteUpsert/Delete)
                                          │
                     every node runs the Materializer (internal/platform/gateway/engine)
                                          │  "am I Config.NodeMAC?"  (hosts.id=1 MAC)
                                          ▼ yes
                <dynamic dir>/node-stats.yml   ◄── gateway.Render(cfg, routes)  (Traefik file provider)
                desired-state.json.gateway     ◄── managed mode only → controller runs `traefik`
```

Nothing is written from an HTTP handler. The gateway node re-renders from replicated state every
5 s (and immediately after a local change), so:

- any node's UI can edit routes/config — the gateway node picks them up;
- moving the gateway = change **Gateway node** in the UI; the old node deletes its file, the new
  one renders (and, in managed mode, the old controller tears Traefik down, the new one starts it);
- a restart re-renders from the DB; the rendered file is a derived artefact.

## Modes

| Mode | Who runs Traefik | Where the dynamic file goes | Requirements |
|---|---|---|---|
| **managed** (Docker) | node-stats, via the controller sidecar (`traefik` compose service) | `/app/data/traefik/dynamic/node-stats.yml` (= `./data/docker/traefik/dynamic` on the host, bind-mounted `:ro` into Traefik) | Docker install with the controller (not managed-externally/dokploy). Ports 80/443 (configurable) free on the gateway node. |
| **managed** (native / Proxmox LXC / .deb) | node-stats itself: downloads the Traefik binary, writes static config + a systemd unit, drives it with `systemctl` | `<cwd>/data/traefik/dynamic/node-stats.yml` (`/var/lib/node-stats/data/...` under the packaged unit) | Linux, systemd, node-stats running as root (the packaged unit does). Outbound HTTPS to github.com once, to fetch the binary. |
| **external** | the operator (existing Traefik / NPM-with-Traefik / …) | `<dynamic_dir>/node-stats.yml` | The dir must be bind-mounted **read-write** into the node-stats container on the gateway node (installer-owned `docker-compose.override.yml`) and equal Traefik's `providers.file.directory`. Entrypoints `web`/`websecure` and cert resolver `le` must exist for TLS routes (or leave TLS off). |

node-stats owns exactly one file (`node-stats.yml`, marked with a `# Generated by node-stats
(gateway)` header) and never touches other files in the directory. It only deletes a file carrying
that header.

## Managed Traefik container

Injected by `setup.BuildComposeContent` when `desired-state.json` carries `gateway.enabled=true`
(see `writeTraefikService`):

- `traefik:v3.3` (override with `NODE_STATS_TRAEFIK_IMAGE` in the stack `.env`), file provider
  only, `--providers.file.watch=true` — no docker socket, no labels;
- entrypoints `web` :80 / `websecure` :443 published on the configured host ports, `ping` :8082
  container-internal (healthcheck + the app's liveness probe at `http://traefik:8082/ping`);
- ACME (`le` resolver, HTTP-01 on `web`) when enabled; `acme.json` persists in
  `./data/docker/traefik/acme`; optional staging CA for testing;
- `mem_limit: 256m`, capped json logs, `--api.dashboard=false`, no telemetry.

The controller starts it with `compose up -d --wait traefik` (a port clash surfaces as a
controller error shown in the UI) and removes it when the gateway is disabled. A **gateway-only**
desired-state change (toggle, ports, ACME) does **not** recreate the app container — the
controller compares the new state against the last applied one (`.applied-state.json`) and skips
the disruptive recreate when only the `gateway` section differs.

## Native (systemd) Traefik — Proxmox LXC and other non-Docker installs

The same **managed** mode works without Docker (`engine/native.go`). On a gateway node that is a
native root install with systemd, the materializer:

1. downloads `traefik_<ver>_linux_<arch>.tar.gz` from GitHub Releases once (newest stable `v3.*`,
   pinned fallback, override with `NODE_STATS_TRAEFIK_VERSION`), verifies it against the release
   checksums file and installs `<data>/traefik/bin/traefik`;
2. writes the static config `<data>/traefik/traefik.yml` (entrypoints `web`/`websecure` bound to
   the configured host ports, `ping` on `127.0.0.1:8082`, file provider on the dynamic dir, ACME
   `le` resolver with `acme.json` in `<data>/traefik/acme/`);
3. writes `/etc/systemd/system/node-stats-traefik.service` (`Restart=always`), `daemon-reload`,
   `enable --now`; restarts the unit only when static config / unit content changed;
4. reports health from the ping endpoint and, when the unit is `failed`, the last journal lines
   (typical: `bind: address already in use` when another web server owns :80).

Disabling the gateway or moving it to another node runs `systemctl disable --now` and removes the
unit; the binary and `acme.json` are kept so re-enabling is instant and keeps its certificates.
`GET /gateway` → `capabilities.manage_kind` is `"docker"`, `"systemd"` or `""` with
`manage_reason` (not root / no systemd / managed externally) — the UI shows it when that node is
selected as gateway from its own dashboard.

In a Proxmox LXC this is the natural setup: the LXC gets the public :80/:443 (or a port-forward
from the PVE host / router), node-stats in it renders routes to the other guests' `ip:port`.
Unprivileged containers are fine — Traefik runs as root inside the container and binds low ports
normally.

## Routes

A route is provider-neutral (`gateway.Route`): `domain` (+ optional `path_prefix`) → `scheme://
target_host:target_port`, flags `tls`, `target_insecure_skip_verify`, access control (`basic_auth`
users — bcrypt-hashed server-side, never returned — and an `ip_allow_list` of CIDRs), `enabled`.

Rendered per route (`gateway.Render`, names prefixed `ns-<route_id>` to never collide with the
operator's objects):

- service `ns-<id>` → `loadBalancer.servers[0].url`; a `serversTransport` with
  `insecureSkipVerify` for self-signed https upstreams;
- router `ns-<id>` on `websecure` with `tls.certResolver: le` (when ACME is on) or `tls: {}`
  (Traefik default cert), plus `ns-<id>-http` on `web` with a permanent `redirectScheme` → https;
  plain routes get one `web` router;
- middlewares `ns-<id>-auth` (basicAuth) and `ns-<id>-ipallow` (ipAllowList) when set.

Routes without basic auth / allow list are badged **public** in the UI — one click exposes an
internal service to the internet, so the form nudges towards adding a user or a CIDR.

**Targets.** The form suggests every container port *published on its host* across the cluster
(`GET /gateway/targets`, from the replicated docker snapshots): that's what is reachable from the
gateway node as `<host ipv4>:<published port>`. Unpublished container ports are not reachable
cross-host and are not offered. "Check reachability" TCP-dials the target from the node serving
the UI (label it accordingly if that isn't the gateway node).

## API (admin)

```
GET    /gateway                    config + routes + this node's status/capabilities
PUT    /gateway/config             {enabled, mode, node_mac, dynamic_dir, http_port, https_port, acme_*}
GET    /gateway/targets            suggested upstreams (published ports cluster-wide)
POST   /gateway/check              {host, port} → {reachable, error?}
POST   /gateway/routes             RouteRequest → 201 {route}
PUT    /gateway/routes/:route_id   RouteRequest (basic_auth password "" keeps the stored hash)
DELETE /gateway/routes/:route_id
```

## Limitations / next steps

- DNS-01 (wildcards, no open port 80) is not implemented — HTTP-01 only. A DNS provider connector
  (credentials in the connectors registry) is the natural next step.
- Only Traefik is rendered. The route model is provider-neutral; a Caddy renderer (admin API, no
  bind mount) or NPM could be added without a schema change.
- Targets are `ip:published-port`. Reaching containers on the gateway node by docker network
  name is not done yet.
- Runtime status (file path, controller phase, Traefik health) and `manage_kind` are only visible on
  the gateway node's own UI; other nodes show where it is rendered. Picking a node that can't run
  managed Traefik from *another* node's UI is only reported on the target node.
